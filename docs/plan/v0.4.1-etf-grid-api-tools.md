# v0.4.1 — etf_grid API & Toolkit Integration

| Field | Value |
|-------|-------|
| **Status** | Planned |
| **Created** | 2026-09-24 |
| **Goal** | `etf_grid` becomes consumable through Runtime's two sanctioned surfaces — an Agno toolkit on the Team Leader (chat) and a versioned FastAPI router (HTTP) — loaded via the extension mechanism defined in `runtime-extensions.md`. |

---

## 1. Background

v0.4.0 delivered the full domain core: four tables, ledger/grid math with
verified parity, FTShare + csindex syncs, and framework-free services
(`compute_daily_signals`, `get_portfolio_status`, `record_trade`,
`list_trades`). Everything works, but the only way to invoke it is a
Python shell — no agent can call it, no client can read it.

This milestone wires the extension into Runtime following
[`docs/architecture/runtime-extensions.md`](../architecture/runtime-extensions.md)
§4–§6: an `Extension.register()` contribution (toolkits + routers), an
in-tree loader with fail-loud startup, toolkits attached to the Team
Leader, routers mounted under `/api/v1/extensions/<kebab-name>/`.

The two deferred loading decisions from v0.4.0 land here: the **extension
registry/loader** (in-tree scan, this milestone) and the **surfaces that
give it a real consumer** (toolkit + api).

## 2. Current State

- `spectres/extensions/etf_grid/`: `config.py`, `types.py`, `models.py`,
  `db.py`, `service.py`, `marketdata.py`, `csindex.py`, `core/` — done (v0.4.0).
- `main.py`: AgentOS with a single Team Leader agent; `agent_os.get_app()`
  returns the FastAPI app. No extension loading exists.
- `agents/team_leader.py`: `create_team_leader_agent(db)` — no `extra_tools`
  parameter yet.
- `tools/builtin.py`: house idiom for tool registration (list of Toolkit
  instances, secrets gate optional tools at startup).

## 3. Scope

### 3.1 In Scope

1. **Extension loader** (`spectres/extensions/base.py`, `loader.py`)
   - `ExtensionContext` / `ExtensionContribution` / `Extension` protocol
     exactly as `runtime-extensions.md` §4 defines.
   - `load_extensions(settings, db, engine) -> list[ExtensionContribution]`:
     in-tree scan of `spectres.extensions` (presence in the tree is the
     opt-in), calls each `register(ctx)`, collects contributions.
   - **Fail-loud**: a `register()` that raises aborts startup naming the
     extension; a broken extension never fails silently (§5.2).
   - `ENABLED_EXTENSIONS` allowlist and `entry_points` discovery remain
     deferred (§9).

2. **`etf_grid` extension entry** (`etf_grid/extension.py`)
   - `name = "etf_grid"`; `register(ctx)` creates its tables via
     `EtfGridBase.metadata.create_all` (idempotent, §6.2 — replaces the
     manual `create_all` step used in v0.4.0), builds and returns the
     toolkit + router. No network calls at load time.

3. **Toolkit** (`etf_grid/toolkit.py`) — Agno `Toolkit`, thin adapter
   (no business logic, §6). Four functions:

   | Function | Service call | Notes |
   |----------|--------------|-------|
   | `get_grid_status()` | `get_portfolio_status()` | Read-only. Positions, latest signals, order lists per symbol. |
   | `refresh_grid_data()` | `sync_candles()` + `sync_valuation()` + `compute_daily_signals()` | The full 3-step pipeline in one call (chat is conversational; per-step control stays on the API). Returns sync counts + signals + skipped. |
   | `record_grid_trade(symbol, trade_date, side, price, quantity, commission_rate, note=None)` | `record_trade()` | Returns the persisted row including system-computed `gross_amount`/`commission`/`net_amount` so the user can verify in-chat. |
   | `list_grid_trades(symbol=None, limit=20)` | `list_trades()` | Recent ledger entries, newest first. |

4. **API router** (`etf_grid/api.py`) — `APIRouter(prefix=
   "/api/v1/extensions/etf-grid")`, thin adapter over the same services:

   | Endpoint | Service call | Notes |
   |----------|--------------|-------|
   | `GET /status` | `get_portfolio_status()` | Main UI data source. |
   | `GET /signals?symbol=&limit=` | `list_signals()` | Signal history with orders. |
   | `POST /signals/compute` | `compute_daily_signals()` | Local compute only (no network). |
   | `POST /sync` | `sync_candles()` + `sync_valuation()` | Network refresh; per-symbol row counts and per-symbol errors in the response (partial failure ≠ 500). |
   | `GET /trades?symbol=&start=&end=&limit=` | `list_trades()` | Ledger query. |
   | `POST /trades` | `record_trade()` | Body mirrors the service signature; 422 on validation errors. |

5. **Runtime wiring** (`main.py`, `agents/team_leader.py`)
   - `create_team_leader_agent(db, extra_tools=None)` — appends extension
     toolkits after `get_builtin_tools()`.
   - `main.py` follows the §5.2 sequence: load extensions between db setup
     and app assembly; routers mounted on `agent_os.get_app()` before
     `serve()`.

6. **Tests and quality**
   - Unit: loader (scan finds etf_grid, contribution shape, fail-loud on a
     broken fake extension), toolkit function outputs with mocked services,
     request/response models.
   - Integration (`db` marker): every endpoint via FastAPI `TestClient`
     against real Postgres (seeded candles/trades/valuation);
     `register()` creates tables idempotently.
   - `ruff check`, `ruff format --check`, `mypy`, `pytest` all pass.

### 3.2 Out of Scope

- **Frontend** (chat cards via `useRenderTool`, standalone grid page) —
  Spectres-Web-Client milestone; this milestone provides the data surfaces
  it will consume.
- **Scheduler/automation** (ADR 0003) — sync stays explicitly triggered,
  now via API/tool instead of a Python shell.
- **HITL confirmation for `record_grid_trade`** — the tool records
  immediately and echoes computed amounts for in-chat verification; the
  confirmation UX arrives with the frontend milestone. Accepted risk:
  a misheard trade is a ledger row, reversible by deleting/re-recording.
- API authentication/authorization — single-user local deployment
  (ADR 0005); multi-tenant ACL comes with the multi-tenancy milestone.
- Per-extension member agent (§9), `ENABLED_EXTENSIONS`, `entry_points`.
- Alembic migrations (`create_all` only).

## 4. Success Criteria

- [ ] Chat flow works end-to-end: asking the Team Leader "今天网格有什么
  操作建议" invokes `get_grid_status` and returns the order lists;
  "帮我记录一笔 513330 买入" invokes `record_grid_trade` and echoes the
  computed amounts.
- [ ] `curl /api/v1/extensions/etf-grid/status` returns the same payload
  shape as `get_portfolio_status()`; all six endpoints respond correctly
  against the dev database.
- [ ] A broken extension (test fixture) aborts startup with a clear
  message naming it.
- [ ] Runtime starts without `ETF_GRID_FTSHARE_API_KEY`; only
  `refresh_grid_data` / `POST /sync` fail with an explicit error.
- [ ] Quality checks pass locally and on GitHub Actions.
