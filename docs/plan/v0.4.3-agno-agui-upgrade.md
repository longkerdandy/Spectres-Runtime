## 1. Background

Online version check (2026-10-09):

| Package | Current (uv.lock) | Latest | Latest release date |
|---------|-------------------|--------|---------------------|
| `agno` | 3.0.10 | 3.1.2 | 2026-10-08 |
| `ag-ui-protocol` | 0.1.19 | 1.0.0 | 2026-09-17 |

Why this milestone exists:

- **AG-UI resume bug fix (primary driver).** `ag-ui-protocol` 1.0 lets a tool
  result (`ToolMessage.content`) arrive as a list of content parts, but the
  AG-UI resume code in agno ≤ 3.0.10 expected a string: a frontend answering a
  paused run with list content got `RUN_ERROR` and the tool never executed.
  agno v3.0.11 fixes this (joins text parts before resolving the pause;
  [PR #10283](https://github.com/agno-agi/agno/pull/10283),
  [agno.com article](https://www.agno.com/articles/the-ag-ui-interface-supports-ag-ui-protocol-1-0)).
  This is directly on the project's critical path: HITL confirmation for
  sensitive operations is a confirmed requirement (AGENTS.md §3.1 item 6,
  ADR 0004), and the web client will send exactly these resume payloads.
- **HITL fixes in 3.1.x.** v3.1.0: continuing a paused run with
  `background` + `stream` no longer duplicates the paused run in its own
  history. v3.1.2: each `@approval` tool call in a run now gets its own
  approval record (previously a second pause in the same run ran against the
  first one's resolution).
- **Protocol 1.0 housekeeping.** `ag-ui-protocol` 1.0 removes the legacy
  `binary` content part (AgentOS answers requests that still send one with
  422), adds modality-specific input parts (`ImageInputPart` etc.), and omits
  null optional fields on serialization. Agno accepts `ag-ui-protocol`
  0.1.15 through 1.0, so the protocol bump rides along with the agno bump.

Impact pre-analysis (3.0.10 → 3.1.2 vs. this codebase):

- The Runtime's entire AG-UI surface is one mount:
  `interfaces=[AGUI(agent=team_leader_agent)]` in `src/spectres/main.py:35`.
- v3.1.0 breaking changes **do not apply**: the `agno_fs` table re-key only
  affects `DbFileSystem` users, and the MCP `default_tools`/`lifecycle_tools`
  opt-in only affects `MCPConfig(tools=[...])` users — the project uses
  neither.
- v3.1.x new features (RBAC/`agno.os.authz`, `DbFileSystem`, conversation
  compaction, `CORSConfig` browser origin policy, follow-ups) are adoption
  choices, not forced changes; `cors_allowed_origins` keeps existing
  behavior.
- No schema migration is documented for the `PostgresDb` session tables the
  project relies on; still verified hands-on in Task 4.
- Likely friction point: `tests/test_main.py` mocks the agent/db and encodes
  assumptions about agno 3.x internals (session-ownership probing, event
  emission) — expect adjustments there rather than in production code.

Rollback strategy: the upgrade is fully contained in `pyproject.toml` +
`uv.lock`; reverting those two files and re-running `uv sync` restores
3.0.10 / 0.1.19 exactly.

### A.2 ag-ui-protocol 0.1.19 → 1.0.0

1. **Protocol frozen at 1.0** (`PROTOCOL_VERSION` = "1.0", schema `$id` at
   `/spec/1.0/schema.json`). AG-UI is this system's *only* client contract
   (ADR 0005; web client AGENTS.md §7.1), so a frozen spec de-risks the
   whole Client layer.
2. **Subagent Events have landed in spec 1.0** — conformance streams
   (`spec/1.0/conformance/streams/subagent-*.json`),
   `docs/spec/1.0/events/subagents.mdx`, and Python SDK models
   (`SubagentInfo`, `MultiAgentCapabilities.subagents`). This resolves the
   protocol-side precondition tracked by ADR 0004 ("protocol-native
   Subagent Events are the end state"). **However**: a code search of agno
   `main` finds no subagent mapping in the AG-UI interface — agno 3.1.2
   still emits the flattened single-voice stream. Conclusion for ADR 0004:
   the end state is now *protocol-ready but not framework-mapped*; a
   Runtime-side custom mapping (ADR 0004 Phase 2+) can be built on stable
   1.0 event types instead of waiting for the spec.
   - Rename pitfall in 1.0: `SubAgentInfo` → `SubagentInfo`,
     `sub_agents` → `subagents`; the old field name silently constructs as
     an extra field (`extra="allow"`) with no error — search code for it,
     don't rely on runtime failures.
3. **List-valued tool results** (`ToolMessage.content` as content-part
   list) — the change that broke pause/resume on agno ≤ 3.0.10 and is fixed
   by agno 3.0.11. Critical path for HITL confirmations (AGENTS.md §3.1.6).
4. **Legacy `binary` content part removed**; modality-specific input parts
   added (`ImageInputPart`, `AudioInputPart`, `VideoInputPart`,
   `DocumentInputPart`). Server now 422s `binary`. Aligns with the planned
   unified message format (text/images/voice, AGENTS.md §3.1.7) — the
   multimodal input path is now standardized. Web client
   (`@ag-ui/client ^0.0.59`) is not expected to send `binary`; verify in
   Task 5.
5. **Serialization omits optional nulls** — payload shape change; TS
   clients tolerate absent optional fields. Note: `@ag-ui/client` 1.0.0
   also shipped (2026-09-17) with an enforcement pipeline and capped
   buffers; upgrading the web client is a separate milestone in that repo.
6. Also added: token-usage-with-cache-writes models, run outcomes,
   capabilities models.

### A.3 agno v3.0.11

- **AG-UI supports ag-ui-protocol 1.0** (the upgrade's primary driver).
- **`cancellation_stage`** (machine-readable `PENDING`/`EXECUTING`/
  `INTERRUPTED`) on `RunOutput`/`TeamRunOutput` and run API schemas —
  useful later for Client-layer cancel UX and for automation-run monitoring
  (ADR 0003).
- **Knowledge-level retrieval pipeline + `MMRReranker` / `RecencyReranker`**;
  the vector-db-level `reranker` param is deprecated. Relevant when the
  knowledge-agent milestone (AGENTS.md §3.1.5) lands — adopt the
  `Knowledge`-level reranker then.
- **Tool hooks fix**: sync hooks returning `function_call(**arguments)` now
  work in the async path. Matters for the Runtime-owned per-member tool ACL
  (ADR 0001 framework gap) if implemented via hooks.
- **MCP fixes** (tool-discovery pagination, `mcp=True` routing parity,
  input-schema descriptions) — relevant to a future MCP-based Edge channel.
- **`TavilyTools` fix** (extract options forwarding) — free improvement for
  the existing web-search tool.
- DeepSeek thinking-mode IDs recognized as reasoning models via
  `OpenAILike` providers (e.g. DashScope) — relevant to model-provider
  flexibility (confirmed decision #3, online APIs).

### A.4 agno v3.1.0

- **`agno.os.authz` RBAC** (role store, scope policy, audit log, user
  directory, pluggable engines incl. fine-grained `fga`) plus JWT-based
  multi-user isolation. Directly overlaps two ADR 0001 framework gaps the
  Runtime currently owns (per-member tool ACL, tenant isolation) and the
  multi-tenant confirmed decision (#2). **Future-milestone candidate:**
  re-evaluate how much custom ACL code is still needed once multi-user
  work starts. Not adopted now (single-user phase).
- **`agno.fs` / `DbFileSystem`** — only breaking change in 3.1.0 (table
  re-key); not used, no impact.
- **HITL fix**: paused run continued with `background` + `stream` no longer
  duplicates itself in history — relevant to ADR 0003 automation runs and
  future confirmation flows.
- MCP config/auth refresh; `AIMLAPITools` (image/video/speech) — noted for
  the long-term voice/multimodal surface only.

### A.5 agno v3.1.1

- Knowledge page-sync progress/cancellation/reporting improvements — only
  relevant to future knowledge-base operations; no current impact.

### A.6 agno v3.1.2

- **Conversation Compaction** (`Agent(compaction=True)`, `CompactionRecord`
  table, derived model payload, stored messages never rewritten, optional
  `search_compacted_history` tool). Strong fit for the Master Agent's
  long-lived sessions and §3.1.4 context-window management — **top
  future-milestone candidate** after this upgrade.
- **Approvals fix**: every `@approval` tool call in a run gets its own
  approval record (previously a second pause reused the first's
  resolution) — directly relevant to confirmation-gated sensitive tools.
- **Browser Origin Policy** (`AgentOS(cors=CORSConfig(...))`, unified
  origin policy across CORS/auth errors/WebSockets/MCP). Current
  `cors_allowed_origins` keeps working; consider migrating when the
  remote-access phases of ADR 0005 begin.
- Configurable follow-ups (chat suggestion UX), HyDE query transform
  (future knowledge RAG), new model providers, `SixtyDBTools` — noted, no
  current impact.

### A.7 Prioritized takeaways

- **P0 (this milestone)**: the upgrade itself — resume fix + two HITL fixes
  serve the confirmed human-in-the-loop requirement; zero breaking changes
  for this codebase.
- **P1 (follow-ups right after)**: update ADR 0004's tracking note
  (Subagent Events are in 1.0; agno mapping still absent); adopt
  `cancellation_stage` when building cancel UX; TavilyTools fix comes free.
- **P2 (future milestones)**: conversation compaction for the Team Leader;
  RBAC re-evaluation vs. Runtime-owned ACL (ADR 0001); `Knowledge`-level
  reranker pipeline for the knowledge-agent; modality-specific input parts
  for the unified message format; `CORSConfig` migration at ADR 0005
  remote-access phase.
