## 2. Context

Agno 3.1.2 carries native model reasoning on `RunContentEvent`, but its AG-UI adapter maps only the text field. Its default run-content handler can also open an assistant text message when an event has no text. Runtime's compatibility patch maps reasoning and closes it before tool calls; this milestone hardens the event boundaries and contract tests without replacing Agno's AG-UI interface.

## 3. Scope

### In Scope

1. Map native `reasoning_content` deltas to AG-UI Reasoning events.
2. Close reasoning before assistant text or a tool call and start a new reasoning message after a tool boundary.
3. Suppress ordinary text-message creation for contentless run-content events.
4. Preserve Agno's required empty assistant parent when a tool call has no text parent.
5. Test plain text, reasoning-only, reasoning/text, sequential and parallel tools, metadata-only content, and terminal cleanup.
6. Keep the compatibility patch documented and removable when Agno implements the behavior upstream.

### Out of Scope

- Restoring reasoning or tool history in the Web Client.
- Custom AG-UI event types, subagent visibility, workflows, or activity streams.
- Model-specific reasoning switches or a second reasoning agent.
- Changes to tool execution, authorization, or persisted session schemas.

## 4. Event Contract

- Reasoning content creates one open Reasoning span until text or a tool starts.
- Text and tool boundaries emit the matching Reasoning end events before the next phase.
- A later reasoning delta after a tool uses a new message id.
- Contentless metadata does not emit `TEXT_MESSAGE_START` or `TEXT_MESSAGE_CONTENT`.
- A tool without a text parent retains Agno's empty assistant parent and `parent_message_id` linkage.
- Run completion and errors leave no open Reasoning or text span.
