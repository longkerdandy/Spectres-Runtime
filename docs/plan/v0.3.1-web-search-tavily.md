## 2. Context

v0.3.0 shipped the browser MVP. Separately, web search was prototyped on Agno's `WebSearchTools` (ddgs meta-search, no API key) plus `WebsiteTools` (`read_url`). Live testing from the owner's network showed the ddgs approach is not viable: of 8 engines only Brave returned results consistently; Startpage/Mojeek/Google/DuckDuckGo were blocked or rate-limited (full matrix in [ADR 0006](../adr/0006-web-search-tool-tavily.md)).

Decision (ADR 0006): adopt **Tavily** via Agno's `TavilyTools`:

- 1,000 free credits/month, no credit card — covers single-user MVP volume.
- Agent-native output: direct answer + pre-extracted clean content per result.
- `search_depth` must be `basic` (1 credit/search); Agno's default `advanced` costs 2 credits and would halve the free tier.
- `WebsiteTools` (`read_url`) stays as the full-page fallback.
- Future option if the free tier is outgrown: custom Toolkit over domestic search APIs (Zhipu BigModel, Volcengine Doubao Search) — see ADR 0006 "Future option".

Key implementation constraint: the owner will supply `TAVILY_API_KEY` later, so the Runtime must start and pass all tests **without** the key — the search tool registers only when the key is configured.

## 3. Scope

### 3.1 In Scope

1. **Dependency changes**
   - Add `tavily-python`; remove `ddgs`.
   - Keep `beautifulsoup4` (required by `WebsiteTools`' reader).

2. **Configuration**
   - Add optional `TAVILY_API_KEY` to `config.py` and `.env.example`.
   - Remove the superseded `SEARCH_BACKEND` setting and its `.env.example` docs.

3. **Tool registration** (`src/spectres/tools/builtin.py`)
   - Replace `WebSearchTools` with `TavilyTools(search_depth="basic")`, registered **only when** `TAVILY_API_KEY` is set (missing key → tool absent, Runtime still starts).
   - Keep `CalculatorTools`, `ShellTools`, `WebsiteTools`.

4. **Tests and quality**
   - Update `test_tools.py`: tools without key (3 toolkits, no Tavily); tools with key (4 toolkits, Tavily present with `basic` depth).
   - Update `test_config.py`: drop `SEARCH_BACKEND` tests, cover `TAVILY_API_KEY` default/override.
   - `ruff check`, `ruff format --check`, `mypy`, `pytest` all pass.

5. **Docs touch-ups**
   - `docs/architecture.md` §7: move Tavily from "decided" to implemented.

### 3.2 Out of Scope

- Obtaining the API key and live smoke tests against the real Tavily API (owner supplies the key; verification happens then).
- Custom domestic-search Toolkit (Zhipu/Doubao) — future option per ADR 0006.
- Search result caching, rate limiting, cost tracking.
- Tool ACL / HITL confirmation for search tools.
- Team Leader instruction/prompt tuning for search behavior.

## 6.1 Result Notes (2026-09-21)

1. **Dependencies**: `ddgs` removed (its 26-package subtree cleaned out); `tavily-python` 0.8.4 added; `beautifulsoup4` retained for `WebsiteTools`.
2. **Registration behavior** (verified against the real `.env`): without `TAVILY_API_KEY` the Runtime registers `calculator`, `shell_tools`, `website_tools` and starts normally; with the key, `tavily_tools` joins with function `web_search_using_tavily` at `search_depth=basic`.

4. **Live smoke test** (real Tavily key, via `POST /agui`): asked for the 2026 Spring Festival holiday arrangement. The agent autonomously called `web_search_using_tavily`, received Tavily's agent-native result (a `### Summary` direct answer plus sourced entries), and produced a final answer citing a real source (a republication of the State Council notice). Full SSE event stream observed: `RUN_STARTED` → `TOOL_CALL_START/ARGS/RESULT/END` → streamed content → `RUN_FINISHED`.
5. **User review**: approved 2026-09-21.
