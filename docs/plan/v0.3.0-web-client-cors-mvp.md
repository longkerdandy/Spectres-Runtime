## 2. Context

v0.2.x delivered the runnable skeleton: Team Leader Agent (single agent, no Team yet), PostgreSQL persistence, AG-UI interface, and a verified Kimi Code LLM path. v0.3.0 is the Runtime half of the MVP; the other half is the new **Spectres-Web-Client** project (sibling directory, its own v0.1.0 plan).

Key constraints and decisions:

- MVP scope is deliberately minimal: single agent chat over AG-UI. No Team/Slaves, no memory, no HITL tools (those land in later milestones; see ADR 0001/0002).
- **MVP topology assumption**: Runtime and Web Client both run on the same home PC; the browser is on that PC too. No Tailscale, no remote access, no cloud anything in this milestone.
- The Web Client is an **independent** project: it serves its own static files and calls the Runtime cross-origin. The Runtime does **not** host the client (keeps Client/Runtime as separate layers; the endpoint-configurable principle from ADR 0005 applies).
- Cross-origin calls (e.g. `localhost:3000` → `localhost:7777`) require CORS on the Runtime. In this same-PC MVP the allowlist contains only local origins; CORS here is a browser convenience, not a security boundary (real access control arrives later with network isolation and service credentials, per ADR 0005).
- Kimi Code constraint discovered during verification: the configured model only accepts `temperature=1`.
- Prior plans: v0.2.0, v0.2.1. Template: `docs/plan/TEMPLATE.md`.

## 3. Scope

### 3.1 In Scope

1. **CORS configuration**
   - Add a `CORS_ALLOWED_ORIGINS` setting (comma-separated list) to `src/spectres/config.py` and `.env.example`, defaulting to local development origins (e.g. `http://localhost:3000`).
   - Apply `CORSMiddleware` to the FastAPI app returned by `agent_os.get_app()` (or use an AgentOS-native CORS option if one exists — verify at implementation time).
   - Must cover the AG-UI SSE endpoint: allow configured origins, `Authorization`/`Content-Type` headers, and credentials off.

2. **End-to-end manual verification (same PC)**
   - Run Runtime (`localhost:7777`) and serve the Spectres-Web-Client build from an independent static server (`localhost:3000`).
   - Verify in a browser: send a message, receive a streaming reply, trigger the calculator tool, reload the page and continue the same thread.
   - Record the exact verification steps in the milestone result notes.

3. **Configuration and docs touch-ups**
   - Fix the `.env.example` comment for `TEAM_LEADER_LLM_TEMPERATURE` (Kimi Code models only accept `1`).
   - Update `README.md`: how to run the Runtime + Web Client MVP on one PC.

4. **Tests and quality**
   - Unit tests: CORS middleware reflects an allowed origin on preflight and rejects a non-allowed origin. No live LLM or database required.
   - `ruff check`, `ruff format --check`, `mypy`, and `pytest` pass.

### 3.2 Out of Scope

- Static hosting of the web client by the Runtime (rejected in favor of an independent client).
- Team / Slave Agent migration, multi-agent dispatch (ADR 0001 — later milestone).
- Long-term memory (Mem0/Hindsight), knowledge base.
- HITL `requires_confirmation` tools and approval UI.
- Authentication / authorization on AG-UI or other routes.
- Docker image for the Runtime, Windows service setup, Tailscale/frp/cloud networking (ADR 0005 — deferred).
- Scheduler / automation triggers (ADR 0003).
- AG-UI custom event mapping for member attribution (ADR 0004 phase 2).

## 6.1 Result Notes (2026-09-21)

End-to-end verification was performed on a single PC (Runtime on `localhost:7777`, Web Client dev server on `localhost:3000`, real Kimi Code LLM):

1. **Quality baseline**: `ruff check`, `ruff format --check`, `mypy` all clean (18 files); `pytest` 20 passed, 3 integration tests deselected by default.
2. **CORS smoke (curl)**: preflight `OPTIONS /agui` with `Origin: http://localhost:3000` returned 200 with `access-control-allow-origin: http://localhost:3000`; the same request with `Origin: http://evil.example.com` returned 400 `Disallowed CORS origin`.
3. **AG-UI smoke (curl)**: `POST /agui` returned a full SSE event stream (`RUN_STARTED` → `TEXT_MESSAGE_*` → `RUN_FINISHED`). A second run asking for `12345 × 6789` triggered the `multiply` calculator tool with complete `TOOL_CALL_START/ARGS/RESULT/END` events and correct arguments.
4. **Browser walkthrough**: against the independently served Spectres-Web-Client (cross-origin `localhost:3000` → `localhost:7777`) — streaming chat renders incrementally, the calculator tool call renders as a tool card, reloading the page continues the same thread (PostgreSQL-backed session), and "New conversation" starts a fresh thread. All steps passed; user approved.
