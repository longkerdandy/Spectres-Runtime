## 1. Background

The project pivoted from "single user behind a shared key" to multi-user
support. Two framework facts shape this milestone (verified against the
pinned agno 3.1.2):

- **Agno only verifies JWTs — it never issues them and never stores
  passwords** (`agno/os/authz/user_directory.py`: "agno does NOT store
  passwords and is NOT an authenticator"). An external IdP must own login,
  registration, and token issuance.
- **Verification key sources are static**: `verification_keys=[...]` /
  `JWT_VERIFICATION_KEY`, or a **local JWKS file** (`jwks_file` /
  `JWT_JWKS_FILE`). There is **no JWKS URL fetching**
  (`agno/os/middleware/jwt.py:154-223`). Key rotation means refreshing the
  file/keys and restarting the Runtime — a hard constraint on IdP choice.

Enabling JWT auth changes the authentication plane: when
`authorization=...` is set, the security-key path is disabled for the auth
middleware (`agno/os/app.py:1766` — `effective_key = None if authorization`),
so the cutover is atomic: JWT on = security key off.

Scope discipline for this milestone (owner decision): **no admin, no
roles** — `Authorization` is used verify-only (`define_role` is never
called), so every authenticated user can use every route. Data isolation is
v0.6.1. Extension multi-user support (etf-grid) is out of scope for the
whole v0.6.x line.

The IdP is decided: **Logto OSS, self-hosted** ([ADR 0009](../adr/0009-idp-logto-self-hosted.md)).
Key properties driving the implementation: signing keys never auto-rotate
(export JWKS once, valid indefinitely; manual rotation = re-export +
Runtime restart); tokens are ES256 JWTs; the Web Client integrates via the
official `@logto/react` SDK.

## 2. Current State

- Runtime has **no auth configured**: no `OS_SECURITY_KEY`, no JWT
  settings; `AgentOS(...)` in `src/spectres/main.py:35` is built without
  `authorization` / `user_directory`.
- All routes (AG-UI `/agui`, extension routers mounted via
  `include_router`, MCP, WebSocket) are open to anyone who can reach the
  port.
- Web Client (separate repo `../Spectres-Web-Client`): pure static SPA, no
  backend, talks directly to `VITE_AGENT_ENDPOINT`; no login UI, no token
  handling (`src/ag-ui.ts` `HttpAgent`, `src/plugins/etf-grid/api.ts`
  `fetch`).
- Auth middleware mechanics already verified: one `AuthMiddleware` on the
  parent app covers all routes incl. extension routers; default exemptions
  are `/`, `/health`, `/info`, `/docs`, `/redoc`, `/openapi.json`,
  `/docs/oauth2-redirect`; OPTIONS preflight passes through.
- `UserDirectory` (agno) gives JIT provisioning from token claims and a
  `disabled` kill-switch enforced at request time.

## 3. Scope

### 3.1 In Scope

1. **IdP selection decision — DONE**
   - Resolved: **Logto OSS self-hosted**, recorded in
     [ADR 0009](../adr/0009-idp-logto-self-hosted.md) (candidates
     evaluated: Casdoor, Pocket ID, Authentik, Keycloak, Kanidm, Dex,
     Ory Hydra+Kratos, managed Clerk/Auth0, self-issued JWT).

2. **Logto deployment & registration**
   - Add a `logto` service (official image `svhd/logto`) to the home
     host's Docker Compose, backed by the existing PostgreSQL (own
     database); one-off `db seed` at first boot; admin Console access
     restricted to LAN/Tailscale.
   - In the Console: create the first admin user; create the Runtime's
     **API resource** (its URI becomes the JWT `aud`); register the Web
     Client as a **public SPA application** (PKCE, redirect/post-logout
     URIs for dev and LAN origins, refresh-token rotation enabled).
   - Export Logto's JWKS to a file the Runtime can read
     (`oidc/.well-known/jwks.json` → committed path is **not** allowed;
     file lives on the host, path via env var). Record the manual
     re-export + Runtime restart procedure for key rotation in the
     runbook.
   - Seed initial family users (no self-registration); document
     add/disable/reset-password flows (Console / Management API).
   - Optional: SMTP connector for self-service password reset — decide
     during implementation; absence means resets are an admin operation.

3. **Runtime wiring** (`src/spectres/config.py`, `src/spectres/main.py`)
   - New required env vars per project convention (no defaults):
     verification material location (`JWT_VERIFICATION_KEY` or
     `JWT_JWKS_FILE` are read by agno directly — decide whether Settings
     wraps them or passes through), expected `aud`/`iss` if enforced.
   - Build `Authorization(verification_keys=... / jwks_file=...,
     audience=...)` and pass `AgentOS(authorization=authz,
     user_directory=True)`.
   - Keep `DOCS_ENABLED` behavior explicit; `/health` must stay open.
   - Startup must fail fast with a clear message when JWT is enabled but no
     key material is present (agno already raises; surface it cleanly).

4. **Runtime tests**
   - Unit (with `agno.os.auth.create_dev_token`): no token → 401; garbage
     token → 401; valid token → 200 — across an AgentOS route, `/agui`,
     and one extension route.
   - JIT provisioning: first valid token creates a UserDirectory row with
     claims mapped (email/name); second request does not duplicate.
   - Disabled user with a still-valid token → denied (kill-switch).
   - Scheduler regression: scheduled `etf_grid_daily_sync` still executes
     under JWT mode (internal service token path unaffected).

5. **Web Client milestone (coordination — code lives in
   `../Spectres-Web-Client`, gets its own plan there)**
   - Login flow via **`@logto/react`**: `LogtoProvider` + `useLogto`,
     sign-in redirect, callback route, sign-out; the SDK handles
     `offline_access` and automatic access-token refresh.
   - Attach `Authorization: Bearer <access_token>` (fetched with the API
     resource as `aud`) in `HttpAgent` headers and the etf-grid `fetch`
     layer; any 401 clears local state and re-enters login.
   - CORS: Runtime origins updated for the deployed client origin;
     `Authorization` allowed in preflight (verify Starlette CORS config).

6. **Cutover & retirement of the shared key**
   - Confirm no client depends on `OS_SECURITY_KEY`; remove it from the
     home host env once JWT mode is live (dev loops switch to
     `create_dev_token`).
   - Keep a documented local-dev path: `create_dev_token` with a dev-only
     verification key (never the production key).

7. **Docs sync**
   - ADR 0009 (Logto) — written with this plan update.
   - `docs/architecture/`: new/updated auth section — plane diagram
     (Logto → JWT → Runtime verify → directory), JWKS re-export/rotation
     runbook, Logto upgrade procedure (alteration CLI).
   - `AGENTS.md` §5: decision 9 already says auth is Runtime-side; add the
     multi-user direction note if wording needs it.
   - ADR 0008: fix the stale reference to the deleted gateway plan (done
     with this plan update).

### 3.2 Out of Scope

- **Roles / admin separation** — all users equal this phase (owner
  decision); managed roles deferred.
- **Data isolation** — v0.6.1. Data stays shared; documented as known
  state.
- **Extension (etf-grid) multi-user anything** — extension routes require a
  valid token but any authenticated user may call them; recorded as the
  v0.6.x contract.
- **Gateway / public exposure** (Tencent Cloud Lighthouse) — postponed;
  auth is verified over LAN/Tailscale first.
- **Service accounts / PAT**, MFA policy enforcement, social-login
  providers beyond the IdP default.
- Account deletion / GDPR-style flows.
