## 2. Context

The long-term design is settled in [Runtime Extensions](../architecture/runtime-extensions.md): one directory per extension, auto-discovery, dependency injection, declarative contributions. This milestone deliberately ships **only the domain core** of the first extension. The loading infrastructure (`base.py`, `registry.py`, auto-discovery, `main.py` wiring) is deferred to the next milestone together with tools and API: without routers or toolkits to mount, the registry would have no real consumer — its only runtime effect would be table creation, which a script does equally well. Deferring keeps this milestone focused on its actual risk: **computational parity**.

The package is placed at its final location `src/spectres/extensions/etf_grid/` from day one (no `extension.py` manifest yet, nothing auto-discovers it), so the next milestone is purely additive — no moves, no import-path changes.

The computation is ported from the owner's proven scripts in `../quant-advisor/backtest/` (strategy semantics documented in that project's `AGENTS.md`):

- `bt_anchor_scan.py::load_with_anchors` — MA60 anchor series.
- `bt_position.py` — `level_of` (5% log-steps vs anchor, clamped), level-diff signal generation (next-day-open execution), `replay_ledger` (lot queue, moving weighted average cost, cost-protection sell pairing at `max(grid boundary, cost×1.05)`), valuation gate for 513530 (930914 dividend-yield percentile < 20% blocks buys).
- `update_data.py` — FTShare remote MCP client (streamable HTTP, `ft_v1_etf_candlesticks`, `FTSHARE_API_KEY` header), ~60 lines of stdlib.
- `update_valuation.py` — csindex public JSON for the 930914 valuation series.

Key constraints:

- **Parity is the acceptance bar**: same inputs must produce the same levels, signals, positions, and costs as quant-advisor. Port, don't redesign.
- **Grid parameters** (step 5%, ¥10k per grid, portfolio symbols/limits, gate threshold) move from hardcoded constants into the extension's `ETF_GRID_*` config fragment — defaults must reproduce today's portfolio.
- **pandas** becomes a Runtime dependency: the proven computation is pandas-based; rewriting it in stdlib risks silent behavioral drift, which violates the parity bar.
- Nothing in this package is wired into Runtime startup; a missing `FTSHARE_API_KEY` only makes sync fail explicitly at call time.

**Implementation proceeds table by table** — each table's schema is
reviewed with the owner and finalized before its code is written.
Finalized so far: `etf_grid_trades` and `etf_grid_candles` (full
schemas in §3.1). Completed increments: the trades ledger (model,
`core/ledger.py` replay, `service.py`, parity script — committed);
the `etf_grid_candles` model plus its storage service functions;
**`config.py` (ETF_GRID_* settings fragment) and `marketdata.py`
(FTShare official SDK sync orchestration)**. Next steps: `core/grid.py`
signal computation and the full signal parity check.
Note the finalized ledger carries explicit `gross_amount` /
`commission_rate` / `commission` / `net_amount` columns (the three
amounts computed at entry from price × quantity and the per-trade rate);
cost basis in replay uses `net_amount`, which is arithmetically
equivalent to quant-advisor's `price×shares + fee` — the parity tests
must prove this.

Owner decisions applied to the ledger design:

- **No CSV migration.** The quant-advisor trade history is considered
  potentially inaccurate and will be re-entered manually; the one-off
  import script was dropped (and with it the need to handle the
  `20260908` date-format anomaly in `trades_513120.csv`).
- **No `init` side.** An opening-position backfill is recorded as a
  plain `buy` — it replays identically, so a separate side was a
  redundant state; the backfill semantics go in `note`.
- **No `csv-import` source.** It was a permanent enum value paying for
  a one-time migration action; `source` is `manual` or `agent`.

## 3. Scope

### 3.1 In Scope

1. **`etf_grid` config** (`config.py`)
   - `ETF_GRID_*` settings fragment: optional `FTSHARE_API_KEY`; grid parameters as structured config (JSON env var, same parsing idiom as `TEAM_LEADER_LLM_EXTRA_HEADERS`). All fields are required env vars (no hardcoded defaults); symbols as FTShare full codes, e.g. `513330.XSHG`.

2. **Storage models** (`models.py`)

   Schemas are finalized one at a time (see §2).

   **`etf_grid_trades` — append-only ledger ✅ FINALIZED**

   | Column | Type | Constraints | Notes |
   |--------|------|-------------|-------|
   | `id` | BigInteger | PK, autoincrement | |
   | `trade_date` | Date | NOT NULL | |
   | `symbol` | String(16) | NOT NULL | FTShare full code, e.g. `513330.XSHG` |
   | `side` | String(8) | NOT NULL, CHECK in (`buy`,`sell`) | opening-position backfill = plain `buy` (note carries semantics) |
   | `price` | Numeric(10,4) | NOT NULL | |
   | `quantity` | Integer | NOT NULL | shares, round lots |
   | `gross_amount` | Numeric(12,2) | NOT NULL | = price × quantity |
   | `commission_rate` | Numeric(8,6) | NOT NULL | per-trade, e.g. 0.001 |
   | `commission` | Numeric(10,2) | NOT NULL | = ROUND(gross_amount × commission_rate, 2) |
   | `net_amount` | Numeric(12,2) | NOT NULL | buy: gross + commission; sell: gross − commission |
   | `source` | String(32) | NOT NULL, default `'manual'` | `manual` / `agent` |
   | `note` | Text | nullable | |
   | `created_at` | DateTime(tz) | NOT NULL, server default now() | |

   Index: `(symbol, trade_date)`. `record_trade()` takes only
   `trade_date, symbol, side, price, quantity, commission_rate, note` —
   the three amount fields are computed at entry (optional override of
   the computed commission/net for broker minimum-fee cases). No
   UPDATE/DELETE paths; mistakes are corrected by reversal rows.

   **`etf_grid_candles` — forward-adjusted daily-K cache ✅ FINALIZED**

   | Column | Type | Constraints | Notes |
   |--------|------|-------------|-------|
   | `symbol` | String(16) | **composite PK** | FTShare full code, e.g. `513330.XSHG` |
   | `trade_date` | Date | **composite PK** | |
   | `open`/`high`/`low`/`close` | Numeric(10,4) | NOT NULL | forward-adjusted (qfq) |
   | `volume` | BigInteger | NOT NULL | shares (800M+ values exist in history) |
   | `fetched_at` | DateTime(tz) | NOT NULL, server default now() | refreshed on every upsert (data freshness marker) |

   Contracts: **qfq basis** (FTShare `ft_v1_etf_candlesticks` with
   `adjust_kind=Forward`) — a dividend recomputes ALL history, so this
   table is **upsert, not append-only**; sync refetches a trailing
   ~90-day window (covers the MA60 window) so re-adjustments self-heal.
   The original script's 10-day lookback only fixes vendor corrections
   — a latent flaw for dividend-paying symbols like 513530, documented
   as a deliberate deviation. Symbols are stored as FTShare full codes
   (e.g. `513330.XSHG`) everywhere — config holds full codes directly,
   with no short-code mapping layer. The PK covers the only access
   pattern (history per symbol, date-ordered); no surrogate id, no
   extra indexes.

   **Draft — to be reviewed before implementation:**
   - `etf_grid_valuation` — 930914 series: date, close, pe_ttm, dyr (dyr nullable).
   - `etf_grid_signals` — computed daily snapshots per symbol: level, prev_level, action, grids, reference prices, gate state.

   Update `docs/architecture/database-schema.md` to register each table as it is implemented.

3. **Domain core** (`core/`, pure pandas — no Agno/FastAPI/SQLAlchemy imports)
   - `grid.py`: anchor series, `level_of`, level-diff signals, next buy/sell trigger prices, valuation-gate state.
   - `ledger.py`: `replay_ledger` (lot queue, weighted average cost, cost-protection sell pairing), position summary per symbol.

4. **Market data** (`marketdata.py`)
   - FTShare MCP client (port the stdlib client), incremental candle sync into `etf_grid_candles` (idempotent: upsert by sym+date).
   - csindex valuation sync into `etf_grid_valuation`.

5. **Application service** (`service.py`)
   - `sync_market_data()`, `compute_daily_signals()` (sync → compute → persist snapshot → return structured dicts), `get_portfolio_status()`, `record_trade()`.
   - Framework-free: callable from tests, a future toolkit, and a future router alike.

6. **Tests and quality**
   - Unit: grid math (levels, signals, trigger prices, gate), ledger replay (pairing, cost protection, weighted cost), config parsing.
   - Integration (`db` marker): models + service against real Postgres.
   - **Parity check**: replay the real trade CSVs through both quant-advisor's `replay_ledger` and the ported `core/ledger.py` (`scripts/verify_etf_grid_replay_parity.py`; historical `init` rows map to buys) — positions, costs, and lot queues must match within floating-point tolerance. Signal parity for historical dates follows once `core/grid.py` lands.
   - `ruff check`, `ruff format --check`, `mypy`, `pytest` all pass.

### 3.2 Out of Scope

- **Extension loading infrastructure** (`base.py`, `registry.py`, auto-discovery, `main.py` wiring) — next milestone, together with the surfaces that give it a real consumer.
- `toolkit.py`, `api.py` — next milestone.
- Frontend: chat cards, standalone page, `useRenderTool` registrations.
- Scheduler/automation triggers (ADR 0003) — sync is invoked manually (script/tests) this milestone.
- HITL confirmation for trade recording.
- Per-extension member agent (deferred per runtime-extensions.md §9).
- Alembic migrations (`create_all` only).

- [ ] `spectres.extensions.etf_grid` package importable at its final path; no discovery/loading machinery exists yet.
