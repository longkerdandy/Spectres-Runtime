# v0.6.1 — Per-User Data Isolation (user_isolation Rollout)

| Field | Value |
|-------|-------|
| **Status** | draft |
| **Created** | 2026-10-19 |
| **Goal** | With per-user login live (v0.6.0), turn on Agno's `user_isolation` so each user sees only their own sessions, runs, and memories; existing single-user data is migrated to its owner; extension (etf-grid) data stays shared by explicit contract. |

---

## 1. Background

v0.6.0 delivers authentication: every request carries a per-user JWT and
every caller is a known directory user — but all users still read and write
the **same** data. This milestone closes that with Agno's opt-in isolation.

Mechanics, verified against the pinned agno 3.1.2:

- **Single database, shared tables, row-level `user_id` column.**
  `agno_sessions`, `agno_runs`, `agno_memories`, `agno_traces`,
  `agno_metrics`, `agno_knowledge` all carry a nullable, indexed `user_id`
  (`agno/db/postgres/schemas.py`). Isolation is query-level filtering
  (`WHERE user_id = :uid`) — **no** per-user schema/DB and no PostgreSQL
  RLS.
- **Convention, not enforcement** (`agno/os/middleware/user_scope.py`):
  framework endpoints call `get_scoped_user_id(request)` on reads and
  `enforce_owner_on_entity(entity, request)` on writes. An endpoint that
  forgets the helper silently bypasses isolation with no error — framework
  routes are covered; anything we add must follow the pattern.
- **Admin break-glass**: a token carrying the `agent_os:admin` scope is
  unscoped (sees all users) because the default scope provider treats token
  scopes as authoritative. No admin role is defined in this phase, but the
  operator can mint an admin-scope dev token for debugging — documented as
  the operations path.
- **Knowledge is shared-capable**: `agno_knowledge.user_id IS NULL` means
  "visible to everyone" — the migration decision must respect this.
- **Scheduler**: the executor authenticates with the internal service
  token; an *unowned* schedule runs unscoped, an *owned* one scopes to the
  owner via `SCHEDULE_OWNER_HEADER`. `etf_grid_daily_sync` targets an
  extension route, which is out of the isolation plane.

Owner decisions framing this milestone: no admin/roles (all users equal);
**Extension multi-user support is excluded** — etf-grid tables gain no
`user_id`, extension routes keep serving shared data to every authenticated
user.

## 2. Current State

- v0.6.0 done: JWT verification + UserDirectory live; every caller is an
  identified user.
- `AgentOS(...)` in `src/spectres/main.py` is built **without**
  `user_isolation`; all data rows currently have `user_id = NULL`.
- `etf_grid_daily_sync` schedule targets
  `/api/v1/extensions/etf-grid/refresh` (extension route, shared data).
- Web Client stores no `user_id` locally beyond what the token carries;
  `thread_id` continuity relies on the Runtime's session store.

## 3. Scope

### 3.1 In Scope

1. **Enable `user_isolation`** (`src/spectres/main.py`, config if needed)
   - `AgentOS(..., user_isolation=True)`; boot-time sanity log line stating
     isolation is on.

2. **Framework-route isolation verification (POC-style, recorded)**
   - Two test users (dev tokens): A's sessions/runs/memories invisible to
     B across list and get endpoints; writes by A never land on B's
     entities (run-into-session ownership check).
   - Admin-scope dev token reads across users (documented break-glass).
   - Knowledge: NULL-`user_id` rows visible to all; user-uploaded rows
     scoped (if the knowledge feature is in use — otherwise deferred with a
     note).
   - Metrics/traces behavior recorded (shared aggregates vs per-user).

3. **Existing-data migration**
   - One-shot script (`scripts/`, following `reset_db.py` conventions):
     assign all existing `user_id IS NULL` rows in
     `sessions/runs/memories/traces` to the owner's directory user id.
   - Knowledge rows: decide per table semantics — default NULL (= shared)
     unless the owner says otherwise.
   - Idempotent, dry-run mode, row counts logged; runbook entry.

4. **Scheduler ownership check**
   - Verify `etf_grid_daily_sync` still executes (unowned schedule +
     internal token + extension route = unaffected).
   - Record what happens to session/run rows a schedule creates under
     isolation (owner attribution or unscoped) in
     `architecture/scheduled-tasks.md`.

5. **Extension exclusion contract (documented, not coded)**
   - `architecture/runtime-extensions.md`: extension routes are outside the
     isolation plane; extension tables have no `user_id`; every
     authenticated user sees the same extension data. Future per-user
     extensions must follow the `user_scope.py` helper pattern.

6. **Tests**
   - Integration (dev DB, dev tokens): two-user matrix on sessions and
     memories (list/get/write); admin break-glass read; migration script
     test (rows reassigned, idempotent re-run).
   - Regression: v0.6.0 auth matrix still green.

7. **Docs sync**
   - `docs/architecture/`: isolation section — mechanism, break-glass
     procedure, extension exclusion, migration record.
   - Plan checkboxes; `AGENTS.md` only if the confirmed-decisions wording
     changes.

### 3.2 Out of Scope

- **Extension (etf-grid) data isolation** — no `user_id` columns, no
  per-endpoint helper wiring in extensions. Explicitly deferred.
- Roles / managed roles / `/authz` admin API, FGA — still no roles phase.
- PostgreSQL RLS or per-user schemas (possible future hardening).
- Per-user knowledge-base partitions beyond verifying framework semantics.
- Gateway / public exposure — unchanged, still postponed.
- Web Client changes (none expected: isolation is server-side; the
  walkthrough just verifies it).

## 4. Success Criteria

- [ ] With isolation on, user B cannot list, read, or write into user A's
  sessions/runs/memories (integration tests + manual walkthrough with two
  browsers/accounts).
- [ ] The admin-scope break-glass token can read across users; the
  procedure is documented.
- [ ] Migration script reassigns all pre-existing rows to the owner, is
  idempotent, and logs counts; verified on a copy/backup of real data.
- [ ] `etf_grid_daily_sync` still runs green after the cutover.
- [ ] A shared (NULL-`user_id`) knowledge row remains visible to both test
  users, or the deferred note is recorded if knowledge is unused.
- [ ] Quality checks (`ruff`, `mypy`, `pytest`) pass locally and on CI.
