## 1. Background

Runtime already enables Agno Scheduler with `user_isolation=True`. Agno 3.1.2
provides the schedule list/detail and run-history read routes, enforces
`schedules:read`, and applies the framework's owner scoping. This milestone
makes those routes a verified product API rather than adding a parallel Runtime
scheduler API.

The product terms map to Agno ownership as follows:

- **Public task**: an unowned system schedule with `user_id IS NULL`, currently
  represented by `etf_grid_daily_sync`.
- **Personal task**: an owned schedule whose `user_id` is the owning user's JWT
  `sub`.

The word “public” describes deployment-wide ownership, not read visibility.
Agno explicitly treats an unowned schedule as a system task rather than a
resource shared with every user. Where a broader product interpretation would
conflict with that definition, Agno's behavior is authoritative:

- ordinary users do **not** see public tasks;
- administrators with `agent_os:admin` see all public tasks and all users'
  personal tasks;
- ordinary users with `schedules:read` see only personal tasks they own.

No new category column, custom role, Runtime role store, ownership query
parameter, or custom visibility rule is introduced.

## 2. Current State

- `src/spectres/main.py` constructs `AgentOS(..., scheduler=..., user_isolation=True)`.
  AgentOS mounts its native `/schedules` router automatically.
- `src/spectres/scheduler.py` registers extension schedules through Agno
  `ScheduleManager`; the ETF Grid system schedule is unowned.
- Logto issues Agno-native JWT scopes. The ordinary `user` role already has
  `schedules:read`; the `admin` role has `agent_os:admin`.
- Agno's native list/detail routes call `get_scoped_user_id(request)`: an
  ordinary caller is filtered to the JWT subject, while an administrator is
  unscoped and can read across users.
- Agno's run-history routes apply the same owner scope. Listing runs also
  checks the parent schedule; fetching one run checks both ownership and that
  its `schedule_id` matches the path.
- `tests/test_user_isolation.py` already proves that the unowned ETF schedule
  is hidden from an ordinary user and visible to an administrator. The other
  read routes and the full two-user authorization matrix still need explicit
  contract coverage.

The required endpoints therefore already exist. No new production router is
expected; implementation work is limited to a defect confirmed against the
pinned Agno behavior, with the native contract remaining authoritative.

## 3. API Contract

### 3.1 Endpoints

| Method | Path | Purpose | Required scope |
|--------|------|---------|----------------|
| GET | `/schedules` | List visible schedules | `schedules:read` or `agent_os:admin` |
| GET | `/schedules/{schedule_id}` | Read one visible schedule | `schedules:read` or `agent_os:admin` |
| GET | `/schedules/{schedule_id}/runs` | List execution history for a visible schedule | `schedules:read` or `agent_os:admin` |
| GET | `/schedules/{schedule_id}/runs/{run_id}` | Read one visible execution record | `schedules:read` or `agent_os:admin` |

These are framework routes, not routes under `/api/v1/extensions`. Preserve
Agno's paths, schemas, status codes, and OpenAPI output.

### 3.2 Visibility and authorization matrix

| Caller | Public task (`user_id IS NULL`) | Own personal task | Another user's personal task |
|--------|---------------------------------|-------------------|------------------------------|
| Ordinary user with `schedules:read` | Not visible; direct reads return 404 | Readable | Not visible; direct reads return 404 |
| Authenticated caller without either accepted scope | 403 | 403 | 403 |
| Administrator with `agent_os:admin` | Readable | Readable | Readable |
| Missing or invalid JWT | 401 | 401 | 401 |

Use 404 for an existing but out-of-scope schedule or run so direct reads do not
disclose another owner's resources. A scoped list with no matching rows returns
200 with an empty `data` array and zero pagination totals.

Ownership always comes from verified server-side identity. Do not add or honor
`user_id`, `owner`, `scope=all`, or similar query parameters. In particular, an
ordinary caller cannot opt into the administrator's unscoped view.

### 3.3 Queries and response envelopes

`GET /schedules` supports Agno's native parameters:

- `enabled`: optional boolean filter;
- `limit`: 1–1000, default 100;
- `page`: integer greater than or equal to 1, default 1.

`GET /schedules/{schedule_id}/runs` supports the same `limit` and `page`
contract. Both list endpoints return:

```json
{
  "data": [],
  "meta": {
    "page": 1,
    "limit": 100,
    "total_pages": 0,
    "total_count": 0,
    "search_time_ms": 0.0
  }
}
```

Schedule responses retain Agno's `ScheduleResponse`, including `id`, `user_id`,
`name`, `description`, `method`, `endpoint`, `payload`, `cron_expr`, `timezone`,
timeout/retry settings, `enabled`, `next_run_at`, provenance fields, and Unix
timestamps. Run responses retain Agno's `ScheduleRunResponse`, including
`schedule_id`, `user_id`, `attempt`, `status`, `status_code`, timing fields,
optional linked run/session ids, error, input/output, and requirements.

Do not add a derived `type=public|personal` response field in this milestone;
clients can distinguish the two categories from `user_id` without changing the
Agno schema.

### 3.4 Run-history isolation

Run history inherits the parent schedule's ownership:

- a personal task's runs are visible only to that owner and administrators;
- a public task's unowned runs are visible only to administrators through these
  APIs;
- a caller cannot use another schedule's id with an accessible run id, or an
  accessible schedule's id with another user's run id, to bypass isolation;
- administrators receive the same cross-user visibility for runs as for
  schedules.

## 4. Scope

### 4.1 In Scope

1. Freeze the four Agno-native GET endpoints above as the v0.6.4 read contract.
2. Verify scope enforcement, owner filtering, administrator break-glass, public
   task visibility, pagination, enabled filtering, and native response schemas.
3. Add real-PostgreSQL integration tests with two ordinary users, one public
   schedule, owned schedules, and owned/unowned schedule runs. Test fixtures
   may seed database rows directly; no production write API is added for setup.
4. Verify missing/invalid authentication, missing scopes, cross-user ids,
   mismatched schedule/run ids, empty lists, and invalid pagination inputs.
5. Update scheduled-task, authentication, and data-isolation documentation with
   the endpoint inventory and the exact visibility matrix.
6. Run the full regression suite and a live JWT walkthrough for ordinary-user
   and administrator reads.

### 4.2 Out of Scope

- Creating, updating, deleting, enabling, disabling, or manually triggering
  schedules. Existing Agno write routes and the current Logto scope assignments
  remain unchanged; “read-only” limits this milestone's new deliverables and
  does not revoke existing framework functionality.
- Making public tasks visible to ordinary users, which would contradict Agno's
  unowned-system-task semantics.
- A custom `/api/v1/...` schedule router, copied Agno response models, custom
  scope provider, new role/scope, new ownership column, or category table.
- Schedule execution changes, SchedulerTools, Agent tools, notifications, or
  Web Client UI implementation.
- Database schema changes, migrations, dependency upgrades, or changes to the
  ETF Grid schedule itself.

## 5. Success Criteria

- [x] All four GET endpoints appear in OpenAPI and return Agno-native response

- [x] An ordinary user sees exactly their own personal schedules in list and
  detail responses; public tasks and every other user's tasks are excluded.

  schedule/run ids cannot disclose a record.

- [x] `enabled`, `limit`, and `page` behave according to Agno, including empty
  pages and validation failures.
- [x] No custom authorization, ownership override, schema, or write endpoint is
  introduced.
- [x] Existing scheduler, authorization, isolation, and extension regression
  suites remain green; standard lint, formatting, type, and test checks pass
